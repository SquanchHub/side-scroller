## User Prompt

Here's a summary of Dave Rensin's "Elephants, Goldfish and the New Golden Age of Software Engineering":
Part 1: It's a Tool, Not a Toy
Most people misuse AI by asking it to research and report in one shot. Better approach — three steps:
Interrogation first: Have the AI interview you with clarifying questions to flesh out what you actually want (15–20 min), pushing back when it gets sycophantic.
Define evaluation criteria: Have a second conversation building a "grading rubric" for what a good answer looks like.
Then hand both the fleshed-out question and the rubric to a fresh deep-research session.
Save the three artifacts (description, criteria, output) for future reuse — this is what compounds value over time.
Part 2: The Elephant-Goldfish Model (EGM) — for software engineering specifically
Elephant = a context-rich AI session (and the Design Doc it produces) that holds all institutional knowledge and decisions.
Goldfish = a brand-new AI session with zero memory, used to test whether the Design Doc is actually self-sufficient.
Core insight: "Design is the new code" — since AI writes the code now, design judgment must live in docs, not in code itself.
Four phases:
Growing the Elephant — pure design discussion, no code. AI proposes the first draft design (not the human), challenged and argued over.
Teaching the Elephant — write the Design Doc iteratively: Problem → Technical Plan → Alternatives (rejected) → Detailed Implementation (every file + rationale).
Goldfish Protocol — stress-test the doc with fresh sessions: comprehension test, critic review (find gaps), implementation-readiness check, then human review.
Implementation — only now write code, strictly per the doc. Then run a "mean" code review where the AI is told to tear its own code apart for quality/readability.

Test the plan doc according to this. Also include a mean code review in the plan after T5 is implemented.
